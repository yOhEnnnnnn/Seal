# Star 玩法设计

## 设计目标

制作一款操作简单、界面克制、适合轻松游玩，但能够持续产生爆发爽感的无尽游戏。

玩家只需要瞄准、左键、空格和一个保命键，不承担移动或复杂技能管理。深度来自一轮弹夹内部的判断：逐颗选择发射方向，让子弹继续反弹积累动量，再决定何时引爆并装填下一轮。

## 核心循环

1. 玩家每次点击朝当前准星方向发射一颗子弹。
2. 初始弹夹有两发，每颗子弹都可以单独瞄准。
3. 子弹命中敌人或墙壁后无限反弹，每次反弹为冲击波充能，命中敌人还会积累动量。
4. 玩家按下空格时，所有子弹在各自当前位置同时引爆。
5. 每颗子弹的动量提高自身爆炸范围和伤害。
6. 引爆完成后弹夹立即装满，玩家开始下一轮发射。

核心体验可以概括为：

> 逐颗发射 → 无限反弹 → 观察位置 → 选择时机 → 原地引爆并装填

## 操作原则

- 鼠标移动：瞄准。
- 鼠标左键：朝准星方向发射一颗子弹；弹夹打空后无法继续发射。
- 空格：让所有场上子弹在当前位置引爆，并装满弹夹。
- `Q`：充能完成后释放以玩家为中心的冲击波。
- 玩家固定在战斗区域中心，不需要移动。
- 敌人接触玩家后立即死亡。
- 死亡后可以花费金币复活，保留本局构筑和进度。

操作数量保持不变，通过时机、目标位置和当前弹道形成决策。

每次点击只从玩家中心发射一颗子弹，不自动连发。玩家可以在两次点击之间重新
瞄准，让同一弹夹中的子弹进入不同轨迹。增加子弹只会扩大弹夹容量，不产生扇形、
散射或自动攻击。鼠标位置不参与爆炸伤害计算。

## 引爆系统

引爆是游戏的主要主动能力，也是后续所有内容的设计中心。

- 每颗子弹在自己的当前位置产生独立爆炸。
- 每颗子弹的动量分别决定自身额外范围和伤害。
- 同一个敌人在一次引爆中最多受到一次爆炸伤害，重叠区域不叠加伤害。
- 子弹没有寿命和反弹次数限制，只能由玩家主动引爆结束本轮。
- 动量在一段时间没有命中后衰减，避免单纯等待成为最优策略。
- 敌人持续接近玩家，等待更高收益的同时也会增加死亡风险。

第一版不加入完美引爆、额外计时条或强制爆炸。先验证观察弹道并主动引爆
本身是否足够有趣。

## 冲击波

- 冲击波使用 `0%～100%` 的能量槽。
- 子弹命中普通敌人获得 `8%`，命中 Boss 获得 `4%`。
- 撞墙不提供能量，避免安全等待成为最优充能方式。
- 能量达到 `100%` 后，按住 `Q` 蓄力，松开时释放圆形冲击波。
- 蓄力时间为 `1.2` 秒，范围从 `64` 增加到 `112`，伤害从 `2` 增加到 `8` 次击打。
- 普通敌人与 Boss 都会按冲击波伤害减少击打次数，不再被无条件清除。
- 使用后能量归零，必须继续让子弹命中敌人才能再次充能。

## 商店设计

商店固定为五项，只强化“发射、反弹、引爆”这条核心链路：

- `AMMO`：增加弹夹容量，每级增加一发。
- `VELOCITY`：提高子弹飞行速度。
- `IMPACT`：提高子弹直接命中的伤害。
- `NOVA SIZE`：提高每颗子弹的基础爆炸范围，范围不设数值上限。
- `NOVA POWER`：提高爆炸伤害。

不加入扇形角度、暴击、幸运、被动金币倍率、额外射击模式或复杂连锁
升级。每项商品都应当能用一句话解释，并立即改变核心循环的手感或收益。
所有商品最多购买 `10` 次。

玩家开局弹夹容量为 `2` 发，金币从 `0` 开始。普通怪每只累计 `0.25` 金币，
击杀四只才结算一枚完整金币；分裂生成的小怪收益更低，Boss 提供独立的大额奖励。
分数与金币完全分开，清场仍会快速涨分，但不会让商店成长同步失控。基础子弹造成 `2` 点命中伤害；
基础爆炸半径为 `26`，伤害为 `2`。玩家仍然被敌人
碰到一次就会死亡，增强集中在主动攻击能力而非生存属性。

## 敌人设计

敌人的职责不是提供大量技能，而是形成适合反弹和原地引爆的目标结构。
首个完整版本只保留普通方块、分裂方块和 Boss。

### 普通方块

- 数量多，构成主要敌群。
- 从战斗区边缘直线接近玩家。
- 用于制造连续反弹和大范围收割。

### 分裂方块

- 死亡后生成多个较弱的小方块。
- 制造适合多点爆炸覆盖的密集目标。

### Boss 方块

- 达到分数阈值后直接进入战场，不切换场景。
- 持续在周围生成小怪。
- 玩家利用小怪积累动量，再在 Boss 附近引爆子弹。
- Boss 被击败后进入更高强度阶段。

所有敌人继续使用统一的纯色伪立体方块风格，通过尺寸、亮度和运动规律
表达差异。只有现有三类敌人无法支撑长期体验时，才考虑增加新品种。

## 无限成长节奏

游戏不设置传统关卡，也不在阶段之间弹出结算卡片。一次游戏持续循环：

> 铺场期 → 反弹积累期 → 高密度期 → Boss 出现 → 大量结算 → 下一阶段

- 分数决定 Boss 出现时机。
- Boss 死亡后提高生成密度和怪物强度。
- 小怪生命随时间持续成长，并吸收约六成的伤害升级与少量弹夹成长，
  让购买仍然有效，同时避免后期敌人变成摆设。
- 压力主要来自更密集的敌群和更高耐久，基础移动速度保持克制。
- 战斗背景保持固定纯色，通过音效和粒子强度表现阶段压力。
- 所有变化在当前场景内完成，不打断玩家操作。
- 小怪成长以数量和组合压力为主，避免单纯堆叠生命值。

## 死亡与复活

- 敌人碰到玩家后触发短暂停帧、白闪和玩家碎裂。
- 场上敌人先向中心收束，再被死亡冲击波逐圈推出。
- 死亡界面出现后，玩家可以支付金币复活。
- 复活时玩家从中心重新组合，释放清场波，附近敌人被移除。
- 被死亡波推出的怪物平滑回到真实位置，动画结束后恢复控制。
- 复活保留分数、时间和升级，价格随复活次数增长。
- 金币不足时，本局才真正结束。

死亡和复活是一段连续演出：死亡负责炸开，复活负责重组。

## 视觉与反馈原则

- 战斗画面保持深色背景、白色伪立体敌人和少量强调色。
- 普通反馈使用白色，引爆使用青色，高动量爆炸可以逐渐接近金白色。
- 重要动作通过停帧、缩放、镜头震动、粒子和音效共同表达。
- 普通命中反馈保持轻量，引爆、Boss 击杀和死亡使用强反馈。
- UI 不遮挡战斗，不通过频繁弹窗打断节奏。

## 开发顺序

1. 完成无限墙壁与敌人反弹、原地引爆和爆炸预览。
2. 调整动量增长与衰减，确定一轮弹夹的理想节奏。
3. 调整弹夹容量和五项商品的价格成长。
4. 完善分裂方块和第一种 Boss，建立基于分数的阶段循环。
5. 根据实际游玩数据整理五项商品的价格和成长曲线。
6. 最后补充音乐层次、阶段配色和长期记录。

## 当前文件职责

- `game.lua`：游戏状态、分数、金币、难度、死亡和复活流程。
- `arena.lua`：对象管理、敌人生成、弹夹轮次、原地引爆、冲击波与场景动画。
- `player.lua`：玩家表现、手动逐发射击、弹夹和升级属性。
- `projectile.lua`：子弹飞行、无限反弹和动量。
- `enemy.lua`：敌人移动、承伤、碰撞和伪立体绘制。
- `effect.lua`：命中、引爆、冲击波、死亡和复活特效。
- `hud.lua`：战斗信息、引爆及冲击波状态和复活界面。
- `sidebar.lua`：常驻商店面板和购买交互。
- `data/`：玩家、敌人、升级、音效和规则配置。
- `tests/run.lua`：核心玩法和状态转换测试。
